# 管理员账号运维

本页说明 AhaMark 三类账号的日常运维边界。账号仅分为 `admin`、`teacher`、`student`；管理员页面不提供角色转换或物理删除，以免越权或造成业务数据失去归属。

## 管理页面

管理员登录后访问 `/admin/accounts`，可以：

- 按用户名、姓名、账号类型和状态查询；
- 创建单个管理员、教师或学生账号；
- 通过 CSV 批量创建教师和学生账号；
- 对选中账号批量启用、停用或强制退出全部设备；
- 按当前搜索和筛选条件导出不含密码的 UTF-8 CSV；
- 修改展示姓名、启用或停用账号；
- 重置其他账号的密码；
- 查看失败登录、长期未登录、多设备账号和活动会话，并撤销指定会话；
- 查看最近账号操作及执行管理员。

停用账号或重置密码会撤销该账号当前全部会话。当前登录的管理员不能停用自己，也不能在此页面重置自己的密码；系统始终要求至少保留一个启用的管理员账号。

批量运维每次最多处理 200 个账号。页面提交前必须显示影响范围并由管理员再次确认，服务端还要求显式确认字段；不存在、当前管理员或违反“至少一个启用管理员”规则的账号会作为逐项错误返回，其他合法账号仍可处理。批量操作及每个目标账号均写入审计。

导出只包含用户名、展示姓名、账号类型、状态、活动会话数和最近活动时间，不包含邮箱、密码哈希或审计详情。为防止 CSV 被电子表格软件解释为公式，以 `=`、`+`、`-`、`@`、制表符或回车开头的展示字段会自动加安全前缀。

## 学生账号与班级关联

创建学生账号不会自动创建学生档案或加入班级。教师在班级学生列表点击“关联账号”，按用户名或账号姓名搜索启用的学生账号，核对学生姓名、学号和登录用户名后确认关联。系统直接保存学生档案到不可变账号 ID 的关系；学生档案中的邮箱只作为可选联系信息，不参与登录账号查找或关联。

同一位教师名下，一个学生账号最多关联一份学生档案；已经关联的账号不会再次出现在该教师的候选列表。停用账号不会删除关联，学生重新启用后仍使用原关联。教师正式开放成绩前，学生端不会展示成绩。

## 安全面板

安全面板提供：过去 24 小时内已识别账号的失败登录次数、活动会话总数、多设备账号数、从未登录账号数和 90 天未活动账号数。失败登录只为数据库中已存在的账号写脱敏事件，不保存提交的用户名、密码或客户端 IP；未知用户名不会写入审计，避免把攻击者输入持久化。

活动会话按最近活动时间排列。管理员可以撤销非当前会话；当前浏览器会话不能从安全面板撤销，以免误将自己锁在操作中。账号停用、密码重置和“强制下线”仍会撤销该账号的全部未撤销会话。

## CSV 批量导入

页面可下载模板。一次最多读取 200 行，支持 UTF-8 BOM、逗号、CRLF、带引号字段以及以下中英文表头：

| 英文表头 | 中文表头 | 说明 |
| --- | --- | --- |
| `username` | `用户名` | 3–64 位；字母或数字开头，仅小写字母、数字、点、下划线和连字符 |
| `display_name` | `姓名` | 必填，最多 120 字 |
| `account_type` | `账号类型` | `teacher`/`教师` 或 `student`/`学生` |
| `password` | `初始密码` | 8–256 个字符 |

浏览器先在本地解析和校验文件，并只提交有效行；密码不会出现在预览、API 返回或审计记录中。服务端仍会重新校验每一行，已存在或重复的用户名会返回逐行错误。管理员账号必须逐个创建，不能通过 CSV 导入。

## 安全与审计

- 所有管理 API 都要求有效管理员会话；写操作继续受 CSRF 保护。
- 数据库只保存密码哈希；创建和重置接口不回显明文密码。
- 创建、批量创建、修改状态或姓名、重置密码都会写入 `AuditLog`。
- 批量启停、强制下线、指定会话撤销和已识别账号失败登录也会写入 `AuditLog`。
- 审计详情只记录账号标识、动作结果和撤销会话数量，不记录密码。
- 不提供公共注册、自助找回、物理删除或直接角色变更。

## 隔离验收

本机合成账号浏览器验收命令：

```powershell
python -m app.cli.seed_admin_e2e
node scripts/admin_accounts_browser_e2e.mjs
```

种子命令只允许 `APP_ENV=test`，且用户名必须使用 `admin-e2e` 前缀。浏览器脚本只接受回环地址和显式合成凭据，覆盖管理员登录、创建教师、密码重置与会话撤销、教师越权拦截、CSV 导入、审计脱敏、停用及拒绝再登录。

本机 SQLite 仅用于功能隔离验收，不能替代 PostgreSQL Alembic 迁移证据。正式部署仍需在目标 Compose/PostgreSQL 环境执行备份、`alembic upgrade head`、服务重启、健康检查和管理员业务复验。
