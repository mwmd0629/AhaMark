# AhaMark 数据与安全边界

适用等级：**C（内部演示或开发测试）**。本清单优先于演示便利性；任何未列明的数据默认不得进入当前系统。

## 1. 数据使用边界

| 场景 | 允许 | 禁止 |
|---|---|---|
| 内部演示/开发/测试 | 无个人信息的合成教师、班级、学生、作业、答卷、成绩和文件；运行时生成的小型安全 fixture | 真实学生姓名、学号、联系方式、答卷、成绩、评语、学校数据；从生产复制或脱敏不足的数据 |
| 标记 | 固定且可审计的 marker，例如 `analytics72.synthetic.invalid`、`performance50.synthetic.invalid` | 无 marker 或与真实域名/真实身份相似的测试数据 |
| 真实教学/试点 | 当前不允许 | 导入、上传、截图、导出或备份任何真实学生数据 |
| 生产 | 当前不允许 | 公网开放、真实租户接入、把开发 Compose 当生产配置 |

合成数据清理只能使用代码中固定 marker、固定教师身份和明确确认参数；必须先打印并核对范围。不得用模糊条件、Bucket 通配符、`docker compose down -v` 或数据库 downgrade 清理数据。

## 2. 日志与诊断

日志可以记录：时间、级别、method、path、status、request ID、Job ID、Submission ID、ReportJob ID、错误代码和脱敏后的运行状态。

日志禁止记录：密码、Cookie、Session token/hash、CSRF token/hash、访问密钥、数据库连接串、签名 URL、文件正文/二进制、完整 OCR 文本、完整学生答案、成绩表、教师评语、个人联系方式或敏感导出内容。异常堆栈也不得拼入这些值。

## 3. 文件、报告和备份敏感性

- 上传原件、页面衍生图、OCR Block、学生答案、成绩 Snapshot、XLSX/PDF/ZIP 报告均按敏感教育数据处理，即使文件名已随机化。
- 数据库备份包含身份、成绩、评分标准、模型建议、教师修改、审计日志和对象引用，必须加密、访问控制、保留期限明确，并且禁止进入 Git。
- MinIO 备份/导出与原 Bucket 同等敏感；不能放在仓库、共享下载目录、测试报告目录或公开对象存储。
- 测试截图、浏览器视频、trace、storage state 和认证状态可能含 Cookie、学生信息与成绩，必须进入受控临时目录并被 Git 忽略。
- 拒绝的文件不得进入 ready 状态；大型恶意 fixture 不进入仓库，优先运行时生成小型结构文件。

## 4. MinIO 与签名 URL

- 对象键必须随机并包含 owner 边界；API 先通过 `StoredFile.owner_id` 与业务资源所有权校验，再允许元数据、下载签名或受控删除。
- Bucket 不得公开；Nginx 不代理 MinIO 控制台。当前开发 Compose 暴露 9000/9001，不能用于公网或生产。
- 签名 URL 是短期 bearer credential，默认 900 秒。不得写入日志、文档、工单、Analytics 证据、浏览器状态或 Git；到期后必须重新鉴权生成。
- “生成签名 URL 成功”不证明 URL 到期、撤销、转发或跨租户风险已完整验证；真实到期等待测试仍为 NOT RUN。

## 5. 孤儿对象处理

- `scan_storage_orphans` 只读比较数据库记录与对象列表；报告可能暴露 Bucket 名和对象键，按内部敏感诊断文件管理。
- 当前报告有 1 条“数据库有记录但对象缺失”和 1 条“对象存在但数据库无记录”。它们不能据此自动删除或自动补写。
- 任何修复必须逐项确认 owner、业务引用、备份状态、生成来源和恢复路径，并由用户明确批准。
- 禁止定时或脚本化的宽泛删除、前缀清理、未知对象清理和 Bucket/Volume 清空。

## 6. Git 边界

应进入 Git：源码、迁移、测试、文档、依赖清单/锁文件、Compose/Nginx 配置、脚本、开源字体及许可证/来源校验。

禁止进入 Git：

- `.env` 及其环境变体、真实 secret、连接串、私钥、证书私钥、Cookie/CSRF/Session 和签名 URL；
- `*.db`、`*.sqlite*`、数据库 dump、备份目录、MinIO 数据与导出；
- `node_modules`、`.next`、虚拟环境、缓存、覆盖率、日志、临时目录和构建输出；
- 生成的 XLSX/PDF/ZIP、测试报告、截图、视频、trace 和浏览器认证状态，除非是经过逐项脱敏审查且明确批准的固定测试 fixture。

`.env.example` 只能包含占位值和安全开发默认值。仓库内合成脚本存在固定演示密码，它们不是生产秘密，但必须视为公开 fixture credential，绝不能在其他环境复用。

## 7. 环境分界

| 环境 | 当前结论 | 数据与控制要求 |
|---|---|---|
| 开发/自动化 | 允许 | 仅合成数据；默认 Provider 能力需显式；Fake Provider 仅非 production；本地凭据不得复用 |
| 内部演示 | 允许，等级 C | 仅固定 marker 合成数据；界面与讲解必须附带能力限制；不得对公网开放 |
| 真实教学试点 | 禁止 | 当前证据不足，不得以“受控”名义提前导入真实数据 |
| 生产 | 禁止 | 当前无完整权限矩阵、容量、恶意文件、TLS/secret/监控和 MinIO 恢复证据；Fake Provider 必须禁用/降级 |

## 8. 本地风险清单

- 工作区存在被忽略的 `.env`，其中敏感配置为非占位值；值未输出。该文件应只留在受控本机，并与 `.env.example` 的新增键人工对齐。
- 工作区存在两个被忽略的 SQLite 数据库。即使当前用途是开发/测试，也不得假定其无敏感数据；本任务未读取内容。
- 大型生成目录 `node_modules/` 与 `apps/web/.next/` 已忽略；缓存和报告目录规则已补强。
- 机密特征静态扫描未发现私钥头、常见 AWS/GitHub/Slack token 或 JWT；这不是专业 secret scanner 的完整替代，也不能证明历史中从未存在秘密。项目已建立连续、可追溯的八部分提交链；第八部分功能基线为 `cc9146a5edf001817915c020f7aa26bc8053b989`。
